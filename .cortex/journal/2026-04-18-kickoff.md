# Autumn Garage kickoff — coordination repo + dogfood target

**Date:** 2026-04-18
**Type:** decision
**Trigger:** T2.1
**Cites:** doctrine/0001-why-autumn-garage-exists, plans/autumn-mail-dogfood, ../autumn-garage-plan.md

> Established Autumn Garage as the coordination repo for Touchstone/Cortex/Sentinel, and Autumn Mail (SwiftUI Gmail client using `gws` + MLX Swift) as the real software dogfood target. Cortex v0.1.0 shipped on Homebrew today, which changed the plan timeline — Phase B isn't pending, it's done.

## Context

The trio of CLIs (Touchstone v1.1.0, Cortex v0.1.0, Sentinel v0.2.0) already compose by file contract per Cortex Doctrine 0002, but there was no shared place for cross-tool decisions or coordinated planning. Early draft of an upgrade plan (see `../autumn-garage-plan.md` v2) sat at `/Users/henry.modisett/Repos/autumn-garage-plan.md` as a loose file — not versioned, not discoverable, not in anyone's repo.

Two problems surfaced during planning:

1. **Where does the plan live?** Not in any one tool's repo (it spans all three). Not in a shared tool library (Doctrine 0002 forbids). Answer: a fourth meta-repo whose job is coordination only.
2. **What does "real dogfood" look like?** Using Cortex on Cortex is circular. The tools need to survive *a project they weren't built for* to prove the integration contract is honest.

## What we decided

- **Autumn Garage (this repo)** is the coordination meta — Doctrine for cross-tool decisions, plans for coordinated workstreams, journal for decisions and dogfood findings. Separate from each tool's own `.cortex/`. Captured in `doctrine/0001`.
- **Autumn Mail** (`autumngarage/autumn-mail`) is the dogfood target — a minimal SwiftUI macOS app that reads and replies to Gmail using a local LLM. Chosen because it stresses the tools along axes they haven't been pushed on: non-Python stack, external experimental CLI dependency, local-LLM-only, small-but-real. Captured in `plans/autumn-mail-dogfood`.
- **Gmail path:** `gws` (Google Workspace CLI from `github.com/googleworkspace/cli`). Real OAuth, real rate limits, explicitly experimental — which is a feature for dogfood.
- **Local LLM path:** MLX Swift (native Apple silicon, no daemon). Ollama HTTP remains a fallback.
- **Plan revision:** Codex critiqued the v2 plan and v3 is the current version (see `../autumn-garage-plan.md` — will be migrated into this repo and updated to reflect Cortex v0.1.0 shipping today).

## What we'd do differently

Not applicable for a kickoff — this is the baseline from which future "what we'd do differently" entries diverge. The one lesson already surfaced: read the downstream tool's current state *before* writing a plan that depends on its roadmap. The v2 plan assumed Cortex Phase B was pending; v3 discovered v0.1.0 shipped today. A five-minute `git log` of Cortex's `.cortex/` would have caught it.
